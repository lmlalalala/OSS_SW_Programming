# 주요 OSS 라이선스 비교 및 선택 기준

## 비교 대상

React의 MIT와 Apache HTTP Server의 Apache-2.0을 비교하였다. 두 라이선스 모두 상업적 사용과 수정·배포를 허용하는 허용적 라이선스이지만 고지 및 특허 조항에 차이가 있다.

| 기준 | MIT — React | Apache-2.0 — Apache HTTP Server |
|---|---|---|
| 상업적 사용·수정·재배포 | 허용 | 허용 |
| 수정 소스 공개 의무 | 라이선스 자체에서 요구하지 않음 | 라이선스 자체에서 요구하지 않음 |
| 배포 시 의무 | 저작권 및 허가 고지 유지 | 라이선스 사본·관련 고지 유지, 변경 파일 표시, 원본 NOTICE가 있으면 관련 고지 전달 |
| 특허 | 명시적 특허 허여 조항 없음 | 기여분에 관한 명시적 특허 허여 및 일정한 특허 소송 시 종료 조항 |
| 상표 | 별도 권리 확인 필요 | 상표 사용 권한을 일반적으로 부여하지 않음 |
| 적합한 상황 | 간단한 조건으로 학습 코드·도구의 재사용을 장려할 때 | 명시적 특허 조항과 조직 차원의 고지 관리가 필요할 때 |

## 이 저장소의 선택: MIT

학습용 스크립트와 자체 작성 문서를 다른 학습자가 쉽게 활용할 수 있도록 MIT를 선택하였다.
조건이 짧아 참여자가 이해하기 쉽고, 저작권·허가 고지를 유지하며 재사용할 수 있다.
특허에 민감한 조직용 제품이라면 Apache-2.0의 특허 조항과 고지 관리 비용을 함께 검토하겠다.

MIT는 모든 자료의 권리를 자동으로 확보해 주지 않는다. 이 저장소의 적용 대상은 소유자가 작성한 코드와 문서이며,
`강의자료/` PDF 등 제3자 자료는 제외한다. 외부 자료를 배포할 때는 원저작자의 허락과 원래 조건을 별도로 확인한다.
의존성을 추가할 때도 프로젝트 라이선스만 보지 않고 각 의존성의 라이선스를 확인한다.
